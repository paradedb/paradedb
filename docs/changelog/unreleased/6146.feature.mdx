An index with `partition_by` now keeps its partitioned layout without a rebuild. A merge whose inputs carry no partition routes them, so rows that arrive through `INSERT` regain a partition on the merges that already run. `CREATE INDEX CONCURRENTLY` and `REINDEX CONCURRENTLY` route their segments in a pass after the build, so a concurrently built index no longer starts unpartitioned.
