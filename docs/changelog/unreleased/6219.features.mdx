A late-materialized string column is now looked up in two physical steps, `TantivyFetchExec` (doc address to term ordinal) and `TantivyDecodeExec` (term ordinal to string), so each can be placed on its own. The new `paradedb.defer_column_fetch` setting (default `on`) picks whether the fetch runs at the decode point or inside the scan, where rows are still in doc order.
