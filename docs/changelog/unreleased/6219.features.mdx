A late-materialized string column is now looked up in two steps: the fast-field read that turns a document address into a term ordinal, and the dictionary read that turns the ordinal into the string. Each step can be placed on its own. The tuning setting `paradedb.defer_column_fetch` (default `on`) keeps the first step next to the second; `off` runs it inside the scan, where rows are still in document order.
