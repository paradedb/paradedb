Suggest products from partial words: typing `wir` should match descriptions containing `wireless`.

## Add an n-gram field and query it

The default index matches whole tokens. Replace the demo `search_idx` with one that also indexes description fragments of three to eight characters under the alias `description_ngram`. The table and model stay the same, and the original indexed fields remain available.

The following block rebuilds the demo index and runs the first suggestion query. Run the index setup once; subsequent keystrokes only need the query. In an application, put the index change in a migration.

<Tabs>
<Tab title="SQL">

```sql
DROP INDEX IF EXISTS search_idx;
CREATE INDEX search_idx ON mock_items
USING paradedb (
  id, description, embedding vector_cosine_ops, category, rating,
  in_stock, created_at, last_updated_date, latest_available_time, metadata, weight_range,
  (description::pdb.ngram(3,8,'alias=description_ngram'))
)
WITH (key_field='id');

SELECT description, rating, category FROM mock_items
WHERE id @@@ pdb.parse('description_ngram:wir')
ORDER BY pdb.score(id) DESC, id
LIMIT 5;
```

const rows = await db
  .select({
    description: mockItems.description,
    rating: mockItems.rating,
    category: mockItems.category,
  })
  .from(mockItems)
  .where(search.parse(mockItems.id, "description_ngram:wir"))
  .orderBy(desc(search.score(mockItems.id)), mockItems.id)
  .limit(5);
console.log(rows);

```python
from django.db import connection
from paradedb import ParadeDB, Parse, Score

with connection.cursor() as cursor:
    cursor.execute("""
    DROP INDEX IF EXISTS search_idx;
    CREATE INDEX search_idx ON mock_items
    USING paradedb (
      id, description, embedding vector_cosine_ops, category, rating,
      in_stock, created_at, last_updated_date, latest_available_time, metadata, weight_range,
      (description::pdb.ngram(3,8,'alias=description_ngram'))
    )
    WITH (key_field='id');
    """)

rows = list(
    MockItem.objects.filter(id=ParadeDB(Parse("description_ngram:wir")))
    .values("description", "rating", "category")
    .annotate(score=Score())
    .order_by("-score", "id")[:5]
)
print(rows)
```

Replace the sample query and its `PrintResults` call in `Program.cs`, keeping the database context and model definitions.

```cs
await dbContext.Database.ExecuteSqlRawAsync("""
    DROP INDEX IF EXISTS search_idx;
    CREATE INDEX search_idx ON mock_items
    USING paradedb (
      id, description, embedding vector_cosine_ops, category, rating,
      in_stock, created_at, last_updated_date, latest_available_time, metadata, weight_range,
      (description::pdb.ngram(3,8,'alias=description_ngram'))

    WITH (key_field='id');
    """);

await dbContext
    .MockItems.Where(item =>
        EF.Functions.Parse(item.Id, "description_ngram:wir")
    )
    .OrderByDescending(item => EF.Functions.Score(item.Id))
    .ThenBy(item => item.Id)
    .Select(item => new { item.Description, item.Rating, item.Category })
    .Take(5)
    .ToListAsync();
```

## Connect the search box

Issue the query after the user enters at least three characters, and debounce requests so each keystroke does not require a round trip. Replace `wir` with the current input and keep the result limit small.

The example uses a fixed query-parser string. Escape query-parser syntax before inserting user text, or use a structured query targeting the alias. See [Query Parser](/reference/full-text/query-parser) and [Ngram](/reference/tokenizers/available-tokenizers/ngrams) for query and tokenizer behavior.
