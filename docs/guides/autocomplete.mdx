Suggest products from partial words: typing `wir` should match descriptions containing `wireless`.

## Add an N-gram field and query it

The default index matches whole tokens. Replace the demo `search_idx` with one that also indexes description fragments of three to eight characters under the alias `description_ngram`. The table and model stay the same, and the original indexed fields remain available.

The following block rebuilds the demo index and runs the first suggestion query. Run the index setup once; subsequent keystrokes only need the query. In an application, put the index change in a migration.

<Tabs>
<Tab title="SQL">

```sql
DROP INDEX IF EXISTS search_idx;
CREATE INDEX search_idx ON mock_items
USING paradedb (
  id, description, embedding vector_cosine_ops, category, rating,
  in_stock, created_at, last_updated_date, latest_available_time, metadata, weight_range,
  (description::pdb.ngram(3,8,'alias=description_ngram'))
)
WITH (key_field='id');

SELECT id, description, rating, category FROM mock_items
WHERE description::pdb.alias('description_ngram') &&& 'wir'
ORDER BY pdb.score(id) DESC, id
LIMIT 5;
```

  .select({
    id: mockItems.id,
    description: mockItems.description,
    rating: mockItems.rating,
    category: mockItems.category,
  })
  .from(mockItems)
  .where(
    search.matchAll(
      search.alias(mockItems.description, "description_ngram"),
      "wir",
    ),
  )
  .orderBy(desc(search.score(mockItems.id)), mockItems.id)
  .limit(5);

## Expose a suggestions endpoint

Add a `GET /api/suggestions?q=wir` handler in your application. Trim the input and return `{"suggestions": []}` without querying when it has fewer than three characters. Otherwise, run only the query above with the input in place of `wir` and serialize the rows as `{"suggestions": [{"id": ..., "description": ..., "rating": ..., "category": ...}]}`. Keep the five-result limit on the server.

Pass the input as a query parameter or ORM value. The match conjunction (`&&&`) requires every generated N-gram to match; this finds word fragments rather than only prefixes. See [Match Conjunction](/reference/full-text/match#match-conjunction) and [Ngram](/reference/tokenizers/available-tokenizers/ngrams) for query behavior.

## Connect the search box

Once your endpoint is in place, this browser example waits 200 milliseconds after typing stops before fetching suggestions. It cancels previous requests and ignores stale responses so an older result cannot overwrite the current input.

```html
<label for="product-search">Find a product</label>
<input id="product-search" type="search" autocomplete="off" />
<p id="search-status" role="status"></p>
<ul id="suggestions"></ul>

<script type="module">
  const input = document.querySelector("#product-search");
  const status = document.querySelector("#search-status");
  const list = document.querySelector("#suggestions");
  let timer;
  let controller;
  let revision = 0;

  input.addEventListener("input", () => {
    const current = ++revision;
    clearTimeout(timer);
    controller?.abort();
    list.replaceChildren();
    const query = input.value.trim();
    status.textContent = "";
    if (query.length < 3) return;

    status.textContent = "Searching…";
    timer = setTimeout(async () => {
      controller = new AbortController();
      try {
        const response = await fetch(
          "/api/suggestions?" + new URLSearchParams({ q: query }),
          { signal: controller.signal },
        );
        if (!response.ok) throw new Error("Search failed");
        const { suggestions } = await response.json();
        if (current !== revision) return;
        for (const product of suggestions) {
          const item = document.createElement("li");
          const link = document.createElement("a");
          // Replace this route with your application's product page.
          link.href = "/products/" + encodeURIComponent(product.id);
          link.textContent = product.description;
          item.append(link);
          list.append(item);
        }
        status.textContent = suggestions.length
          ? suggestions.length + " suggestions"
          : "No matching products";
      } catch (error) {
        if (current === revision && error.name !== "AbortError") {
          status.textContent = "Search unavailable. Try typing again.";
        }
      }
    }, 200);
  });
</script>
```

Suggestions are ordinary links: users can reach them with Tab and activate them with Enter. This example does not implement an arrow-key combobox. Use `textContent` when rendering descriptions so product data is displayed as text.

## Check the interaction

Type `wi`: no request should run. Continue to `wir`: matching products should appear. With network throttling enabled, type quickly and clear the field; late responses must not restore old suggestions. Try an unmatched phrase and a failed request to check the empty and error messages.
