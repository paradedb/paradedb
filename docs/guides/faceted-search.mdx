Return product hits and facet counts together, so a search page can show results alongside category and rating filters. This pattern is called faceted search.

## Define the filter state

Keep the search text and selected filters in the page URL, for example `?q=shoes&category=Footwear&min_rating=4`. This lets users share a search and use the browser's Back button. A category selection is an exact value; the rating selection is a minimum.

On the server, validate the rating as an integer from 1 to 5 and pass all values as bound parameters or ORM values. Omit a filter's predicate when it is not selected.

## Retrieve hits and buckets

The query below represents a search for shoes with Footwear and a minimum rating of four selected. It returns the five highest-rated products. The window aggregations count categories and ratings over all matching rows, before the result limit.

<Tabs>
<Tab title="SQL">

```sql
SELECT id, description, rating,
       pdb.agg('{"terms": {"field": "category"}}') OVER () AS categories,
       pdb.agg('{"terms": {"field": "rating"}}') OVER () AS ratings
FROM mock_items
WHERE description ||| 'shoes'
  AND category = 'Footwear'
  AND rating >= 4
ORDER BY rating DESC, id
LIMIT 5;
```

import { and, desc, eq, gte } from "drizzle-orm";
import { search } from "@paradedb/drizzle-paradedb";

const rows = await db
  .select({
    id: mockItems.id,
    description: mockItems.description,
    rating: mockItems.rating,
    categories: search.agg({ terms: { field: "category" } }).over(),
    ratings: search.agg({ terms: { field: "rating" } }).over(),
  })
  .from(mockItems)
  .where(
    and(
      search.matchAny(mockItems.description, "shoes"),
      eq(mockItems.category, "Footwear"),
      gte(mockItems.rating, 4),
    ),
  )
  .orderBy(desc(mockItems.rating), mockItems.id)
  .limit(5);

console.log(rows);
console.log(rows[0]?.categories, rows[0]?.ratings);

<Tab title="SQLAlchemy">

```python
from sqlalchemy import select
from sqlalchemy.orm import Session
from paradedb.sqlalchemy import facets, pdb, search

base = (
    select(MockItem.id, MockItem.description, MockItem.rating)
    .where(search.match_any(MockItem.description, "shoes"), MockItem.category == "Footwear", MockItem.rating >= 4)
    .order_by(MockItem.rating.desc(), MockItem.id)
    .limit(5)
)
stmt = base.add_columns(
    pdb.agg(facets.terms(field="category")).over().label("categories"),
    pdb.agg(facets.terms(field="rating")).over().label("ratings"),
)
with Session(engine) as session:
    rows = session.execute(stmt).all()
    print(rows)
    if rows:
        print(rows[0].categories, rows[0].ratings)
```

## Build the response

Return a single response containing the product list and the two bucket arrays. Use each terms aggregation's `buckets` array: `key` is the filter value and `doc_count` is its matching count. For window aggregations, read the repeated aggregates from the first row and leave them out of individual product objects.

The limit applies to the product list, not the bucket counts. Do not use the length of the returned list as the total number of matches. If there are no hits, return empty product and bucket arrays.

## Update the sidebar

Render category buckets as single-select choices and rating buckets as counts for individual ratings. A bucket for rating four counts exactly four-star products; it is not the count for a “4 and up” choice.

When a user changes a filter, update the URL, rerun the query, and replace both results and counts together. These counts include the selected filters: choosing Footwear removes other categories from the returned buckets. Keep selected filters visible independently of the buckets, with a clear action, so users can recover from an empty result set.

For a sidebar that keeps showing alternatives in an already-selected category, run a separate category aggregation without that category predicate. Keep the search text and other filters on that query. See [Facets](/reference/aggregates/facets) for the query shape and [Terms](/reference/aggregates/bucket/terms) for bucket options.

## Check the interaction

Start with `shoes` and no filters, select Footwear, then raise the minimum rating. Confirm that every result satisfies the filters and the counts change with them. Try a category with no matching shoes: the page should show no results while keeping the selected category and its clear action visible.
