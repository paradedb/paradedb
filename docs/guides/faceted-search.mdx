Return product hits and facet counts together, so a search page can show results alongside category and rating filters.

Complete [Connect Your App](/start/connect-your-app) and [Create Your First Index](/start/create-your-first-index) first. These examples use the same `mock_items` table, model, and database connection. Run them in the shell or application you configured there.

For Drizzle, load any additional imports with `await import(...)`, then paste the query body in the REPL’s `.editor` mode as described in [Connect Your App](/start/connect-your-app#drizzle). For EF Core, replace the sample query and its `PrintResults` call in `Program.cs`, keeping the database context and model definitions.

## Retrieve hits and buckets

Search for shoes and return the five highest-rated products. The window aggregations count categories and ratings over all matching rows, before the result limit.

<CodeGroup>

```sql SQL
SELECT id, description, rating,
       pdb.agg('{"terms": {"field": "category"}}') OVER () AS categories,
       pdb.agg('{"terms": {"field": "rating"}}') OVER () AS ratings
FROM mock_items
WHERE description ||| 'shoes'
ORDER BY rating DESC, id
LIMIT 5;
```

```ts Drizzle
import { desc } from "drizzle-orm";
import { search } from "@paradedb/drizzle-paradedb";

const rows = await db
  .select({
    id: mockItems.id,
    description: mockItems.description,
    rating: mockItems.rating,
    categories: search.agg({ terms: { field: "category" } }).over(),
    ratings: search.agg({ terms: { field: "rating" } }).over(),
  })
  .from(mockItems)
  .where(search.matchAny(mockItems.description, "shoes"))
  .orderBy(desc(mockItems.rating), mockItems.id)
  .limit(5);

console.log(rows);
console.log(rows[0]?.categories, rows[0]?.ratings);
```

```python Django
from paradedb import MatchAny, ParadeDB

queryset = (
    MockItem.objects.filter(description=ParadeDB(MatchAny("shoes")))
    .order_by("-rating", "id")[:5]
)
rows, facets = queryset.facets("category", "rating", include_rows=True)
print(rows)
print(facets)
```

```python SQLAlchemy
from sqlalchemy import select
from sqlalchemy.orm import Session
from paradedb.sqlalchemy import facets, pdb, search

base = (
    select(MockItem.id, MockItem.description, MockItem.rating)
    .where(search.match_any(MockItem.description, "shoes"))
    .order_by(MockItem.rating.desc(), MockItem.id)
    .limit(5)
)
stmt = base.add_columns(
    pdb.agg(facets.terms(field="category")).over().label("categories"),
    pdb.agg(facets.terms(field="rating")).over().label("ratings"),
)
with Session(engine) as session:
    rows = session.execute(stmt).all()
    print(rows)
    if rows:
        print(rows[0].categories, rows[0].ratings)
```

```ruby Rails
relation = MockItem.search(:description)
                   .match_any("shoes")
                   .with_agg(
                     categories: ParadeDB::Aggregations.terms(:category),
                     ratings: ParadeDB::Aggregations.terms(:rating)
                   )
                   .select(:id, :description, :rating)
                   .order(rating: :desc, id: :asc)
                   .limit(5)

rows = relation.to_a
puts rows.inspect
puts relation.aggregates.inspect
```

```cs EF Core
var rows = await dbContext
    .MockItems.Where(item => EF.Functions.MatchAny(item.Description, "shoes"))
    .OrderByDescending(item => item.Rating)
    .ThenBy(item => item.Id)
    .Select(item => new
    {
        item.Id,
        item.Description,
        item.Rating,
        Categories = EF.Functions.AggOver(new { terms = new { field = "category" } }),
        Ratings = EF.Functions.AggOver(new { terms = new { field = "rating" } }),
    })
    .Take(5)
    .ToListAsync();

foreach (var row in rows)
    Console.WriteLine($"{row.Description}: {row.Categories}; {row.Ratings}");
```

## Render the sidebar

Use each terms aggregation’s `buckets` array for filter choices: `key` is the field value and `doc_count` is its matching count. The same aggregations accompany each returned row; read them once. Django and Rails expose helpers to collect them separately. If there are no hits, show an empty result set and empty facets.

When a user selects a filter, add it to the search predicate and rerun the query. These counts reflect the filtered result set, including the selected filter. See [Facets](/reference/aggregates/facets) for the query shape and [Terms](/reference/aggregates/bucket/terms) for bucket options.
