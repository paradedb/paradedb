Build a “related products” list from the words in a product description, without generating vector embeddings.

## Find related products

Product `3` is “Sleek running shoes” in the demo data. Use its description as the source, exclude the product itself, and order the remaining matches by relevance.

<Tabs>
<Tab title="SQL">

```sql
SELECT id, description, pdb.score(id) AS score
FROM mock_items
WHERE id @@@ pdb.more_like_this(3, ARRAY['description']) AND id <> 3
ORDER BY score DESC, id
LIMIT 5;
```

</Tab>

<Tab title="Drizzle">

Load any additional imports with `await import(...)`, then paste the query body in the REPL’s `.editor` mode as described in [Connect Your App](/start/connect-your-app#drizzle).

```ts
import { and, desc, ne } from "drizzle-orm";
import { search } from "@paradedb/drizzle-paradedb";

const rows = await db
  .select({
    id: mockItems.id,
    description: mockItems.description,
    score: search.score(mockItems.id),
  })
  .from(mockItems)
  .where(
    and(
      search.moreLikeThisId(mockItems.id, 3, { fields: ["description"] }),
      ne(mockItems.id, 3),
    ),
  )
  .orderBy(desc(search.score(mockItems.id)), mockItems.id)
  .limit(5);
console.log(rows);
```

<Tab title="Django">

```python
from paradedb import MoreLikeThis, ParadeDB, Score

rows = list(
    MockItem.objects.filter(id=ParadeDB(MoreLikeThis(id=3, fields=["description"])))
    .exclude(id=3)
    .annotate(score=Score())
    .order_by("-score", "id")
    .values("id", "description", "score")[:5]
)
print(rows)
```

<Tab title="SQLAlchemy">

```python
from sqlalchemy import select
from sqlalchemy.orm import Session
from paradedb.sqlalchemy import pdb, search

stmt = (
    select(MockItem.id, MockItem.description, pdb.score(MockItem.id).label("score"))
    .where(search.more_like_this(MockItem.id, document_id=3, fields=["description"]), MockItem.id != 3)
    .order_by(pdb.score(MockItem.id).desc(), MockItem.id)
    .limit(5)
)
with Session(engine) as session:
    print(session.execute(stmt).all())
```

<Tab title="EF Core">

Replace the sample query and its `PrintResults` call in `Program.cs`, keeping the database context and model definitions.

```cs
var moreLikeThisOptions = new MoreLikeThisOptions { Fields = new[] { "description" } };
var rows = await dbContext
    .MockItems.Where(item => EF.Functions.MoreLikeThisId(item.Id, 3, moreLikeThisOptions) && item.Id != 3)
    .OrderByDescending(item => EF.Functions.Score(item.Id))
    .ThenBy(item => item.Id)
    .Select(item => new { item.Id, item.Description, Score = EF.Functions.Score(item.Id) })
    .Take(5)
    .ToListAsync();
foreach (var row in rows)
    Console.WriteLine($"{row.Id}: {row.Description} ({row.Score})");
```

## Choose what makes a product similar

Restricting the input fields to `description` avoids matching products solely because their rating or category is the same. Add other supported fields when those attributes should contribute to similarity. The query may return fewer than five rows when few descriptions share terms.

For a product that is not stored in the table, pass a custom document instead of an ID. See [More Like This](/reference/full-text/more-like-this#using-a-custom-input-document) for that syntax and term-selection options.
