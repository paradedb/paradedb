## ParadeDB Cloud

ParadeDB Cloud is fully managed ParadeDB: first-class search from Postgres, with a developer experience to match. It's now available in private preview. [Sign up](https://auth.paradedb.com/sign-up) to get started.

## Cloud Platforms

The following guides and integrations deploy ParadeDB Community using our Docker image, which bundles Postgres and `pg_search`, with persistent storage:

- [Railway](/operate/deploy/cloud-platforms/railway) — One-click deploy to Railway
- [Render](/operate/deploy/cloud-platforms/render) — One-click deploy to Render
- [Fly.io](/operate/deploy/cloud-platforms/fly) — Deploy on Fly.io
- [DigitalOcean](/operate/deploy/cloud-platforms/digitalocean) — Deploy on a DigitalOcean Droplet
- [Dokku](/operate/deploy/cloud-platforms/dokku) — Deploy with Dokku

For managed Kubernetes services such as Amazon EKS, Google GKE, and Azure AKS, or platforms that support custom Helm charts such as Red Hat OpenShift, Rancher, Porter, and Qovery, start with the [Kubernetes deployment guide](/operate/deploy/self-hosted/kubernetes).

## Self-Hosted ParadeDB

ParadeDB can be deployed as an [extension](/operate/deploy/self-hosted/extension) inside an existing self-hosted Postgres or via our [Kubernetes Helm chart](/operate/deploy/self-hosted/kubernetes), which is based on the [CloudNativePG](https://cloudnative-pg.io/) Helm chart. If a self-hosted production deployment needs failover or read replicas for ParadeDB queries, use ParadeDB Enterprise and configure [high availability](/operate/deploy/self-hosted/high-availability).

## ParadeDB BYOC

[ParadeDB BYOC (Bring Your Own Cloud)](/operate/deploy/byoc) is a managed deployment of ParadeDB Enterprise inside your AWS or GCP account. Please [contact sales](mailto:sales@paradedb.com) for access.
