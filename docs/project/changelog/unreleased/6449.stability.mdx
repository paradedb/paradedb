Fixed a `bitmap intersection stream ... claimed twice` error from a Top K search over a bitmap intersection that built a second scorer for the same segment, either because its first batch lost rows to visibility and it queried again, or because a window aggregate ran its own search after the Top K one. A serial scan opens a fresh iterator for each pass, and a parallel scan pre-mints the shared iteration states its passes need, so every pass probes the same bitmap (#6403).
