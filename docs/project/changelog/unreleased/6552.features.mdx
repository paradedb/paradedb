A multi-field `partition_by` now cuts its first field into global ranges and each later field inside them, so a range co-partitioned join on the first field takes whole segments. Indexes built before this keep their layout until they are reindexed. A `field=N` count, as in `partition_by = 'id=8, owner_user_id'`, caps how many ranges a field is cut into; `CREATE INDEX` rejects counts that multiply past an explicit `target_segment_count`. A range co-partitioned join now cuts on whichever side's segment edges give the shorter scan, weighing the rows the cuts land inside on both sides and the tasks the edges can seat, instead of always taking the larger side's edges.
