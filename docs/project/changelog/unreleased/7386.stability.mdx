- Creating a ParadeDB index on a primary no longer stops WAL replay on a ParadeDB Community physical standby; only a query that uses a ParadeDB index on the standby fails, with a `feature not supported` error. After the standby is promoted, the ParadeDB indexes it received through replication refuse queries with the same error until `REINDEX` rebuilds them, while tables, writes and every other index keep working. The primary now names the index in the WAL record it writes when an index is built or vacuumed, and the standby marks the index while replaying it, which is how indexes that predate the standby are covered; a base backup taken from a standby carries the marks and its ParadeDB indexes need `REINDEX` after a restore, while crash recovery and restores of backups taken from the primary are not affected (#6007).
