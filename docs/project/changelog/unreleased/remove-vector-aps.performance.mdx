Stacked IVF list selection now scales with the number of clusters a query asks to probe, so every stacked IVF index can see different recall and latency. After the size-`k` heap fills, a stacked level can also stop when enough consecutive list members leave the worst heap entry unchanged (patience scales with `k`). Otherwise the probe stops on the work budget (`paradedb.vector_cluster_max_probe`) or when the ranking runs out. L2 and cosine indexes at 128 dimensions or fewer also no longer stop early through geometry-based adaptive partition scanning. `paradedb.vector_router_recall_target` and `paradedb.vector_recall_target` remain accepted and have no effect.
