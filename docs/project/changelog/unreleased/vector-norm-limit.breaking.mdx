Adding a vector to an L2 (`vector_l2_ops`) or inner-product (`vector_ip_ops`) field of a ParadeDB index now fails when the vector's squared norm exceeds `f32::MAX / 8` (a norm above about 6.5e18), with the error `vector in field '<name>' (doc <id>) has a squared norm above the limit of 4.253529586511731e37`. Such vectors overflowed the index's single-precision arithmetic, and inner-product searches could not return them. Cosine fields accept any finite vector. Vectors already stored in an index are not re-checked, but `REINDEX` of an index holding one fails with this error.
