Before text is indexed, it is first split into searchable units called tokens.

The default tokenizer in ParadeDB is the [unicode_words tokenizer](/reference/tokenizers/available-tokenizers/unicode). It splits text according to word boundaries defined by the Unicode Standard Annex #29 rules. All characters are lowercased by default. To visualize how this tokenizer works, you can cast a text string to the tokenizer type, and then to `text[]`:

```sql
SELECT 'Hello world!'::pdb.unicode_words::text[];
```

```ini Expected Response
     text
---------------
 {hello,world}
(1 row)
```

On the other hand, the [ngrams](/reference/tokenizers/available-tokenizers/ngrams) tokenizer splits text into "grams" of size `n`. In this example, `n = 3`:

```sql
SELECT 'Hello world!'::pdb.ngram(3,3)::text[];
```

{/* * codespell:ignore-begin * */}

```ini Expected Response
                      text
-------------------------------------------------
 {hel,ell,llo,"lo ","o w"," wo",wor,orl,rld,ld!}
(1 row)
```

{/* * codespell:ignore-end * */}

Choosing the right tokenizer is crucial to getting the search results you want. For instance, the simple tokenizer works best for whole-word matching like "hello" or "world", while the ngram tokenizer enables partial matching.

To configure a tokenizer for a column in the index, simply cast it to the desired tokenizer type:

```sql
CREATE INDEX search_idx ON mock_items
USING paradedb (id, (description::pdb.ngram(3,3)))
WITH (key_field='id');
```

## Posting Norms

For text fields used in top-k BM25 queries, set `pnorms=true` on the tokenizer
cast to store field-length norms alongside postings:

```sql
CREATE INDEX search_idx ON mock_items
USING paradedb (id, (description::pdb.simple('pnorms=true')))
WITH (key_field='id');
```

This option defaults to `false` and applies only to the selected field. It can
reduce scattered reads during scoring, at the cost of additional index storage
and longer index builds and merges. Document-addressed field norms are retained.

Posting norms require an indexed text field with `fieldnorms=true`. Literal
tokenizers default to `fieldnorms=false`, so they require both options explicitly.
JSON and JSONB fields do not support posting norms; extract a text value first
if needed. Existing indexes retain their configuration.
