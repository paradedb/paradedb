title: Tuning Recall and Latency
description: Trade recall against latency for vector search

---

Vector search is approximate: it probes a subset of the index's vector clusters rather than scanning every vector. Adaptive probing uses the rate of promising candidates to decide when to stop. Tune search effort against measured recall and latency for your workload:

```sql
SET paradedb.vector_search_effort = 4.4;
```

<ParamField body="paradedb.vector_search_effort" default={4.4}>
  Larger values widen the router window and require a greater reduction in the
  admission rate before stopping. The value must be at least `0.000001`. Effort
  is not a recall probability or guarantee; calibrate it using queries with
  known nearest neighbors.
</ParamField>

<ParamField body="paradedb.vector_adaptive_probing" default="on">
  Enables admission-based early stopping. Set to `off` to use the probe-work
  ceiling without adaptive stopping.
</ParamField>

<ParamField body="paradedb.vector_cluster_max_probe" default={0}>
  Limits probe work as a fraction of the index's cluster capacity. Values range
  from `0` to `1.0`. Zero selects automatic headroom: `1.0` when adaptive
  probing is enabled and `0.02` otherwise. Positive values impose an explicit
  work ceiling, checked between clusters.

Queries can stop earlier when the adaptive criterion is met or the router's
candidate list is exhausted. Setting this ceiling to `1.0` alone does not
guarantee an exhaustive search.

</ParamField>

<Note>
  Recall also depends on the index's `training_sample_ratio` and
  `max_leaf_size`, applied whenever a segment is clustered. See [Index
  Options](/reference/indexing/indexing-vectors#index-options).
</Note>

## Inspecting Vector Indexes

Use `vector_info` to inspect vector storage and `vector_config` to check build settings. These examples inspect the `embedding` field of `search_idx`:

<CodeGroup>
```sql SQL
SELECT * FROM paradedb.vector_info('search_idx'::regclass, 'embedding');
SELECT * FROM paradedb.vector_config('search_idx'::regclass, 'embedding');
```

```ts Drizzle
import { diagnostics } from "@paradedb/drizzle-paradedb";

await db.execute(diagnostics.vectorInfo("search_idx", "embedding"));
await db.execute(diagnostics.vectorConfig("search_idx", "embedding"));
```

```python Django
from paradedb import paradedb_vector_info, paradedb_vector_config

paradedb_vector_info('search_idx', 'embedding')
paradedb_vector_config('search_idx', 'embedding')
```

```python SQLAlchemy
from paradedb.sqlalchemy import diagnostics

diagnostics.paradedb_vector_info(engine, "search_idx", "embedding")
diagnostics.paradedb_vector_config(engine, "search_idx", "embedding")
```

```ruby Rails
ParadeDB::Diagnostics.vector_info("search_idx", "embedding")
ParadeDB::Diagnostics.vector_config("search_idx", "embedding")
```

```cs EF Core
await dbContext.Database.VectorInfo("search_idx", "embedding").ToListAsync();
await dbContext.Database.VectorConfig("search_idx", "embedding").ToListAsync();
```

</CodeGroup>
