Vector search is approximate: it probes a subset of the index's vector clusters rather than scanning every vector. Probing more clusters improves recall (i.e. how often the true nearest neighbors are returned) at the cost of higher latency. One session-level setting controls this tradeoff:

```sql
SET paradedb.vector_cluster_max_probe = 0.02;
```

<ParamField body="paradedb.vector_cluster_max_probe" default={0.02}>
  The recall/latency driver: a ceiling on how much probe work a query may
  spend, expressed as a fraction of each segment's clusters. For instance, at
  the default value of `0.02`, at most 2% of a segment's cluster-scan work is
  spent. Must be between `0.000001` and `1.0`, where `1.0` allows an
  exhaustive scan.

Within the ceiling, clusters that provably cannot improve the current top-K
are skipped automatically using per-cluster bounds stored in the index; this
skipping never reduces recall, so raising the ceiling only ever improves it.

</ParamField>

<Note>
  Recall also depends on the index's `training_sample_ratio` and
  `max_leaf_size`, set at build time. See [Index
  Options](/reference/indexing/indexing-vectors#index-options).
</Note>

## Quantization settings

The index-wide `quantization` option controls the filtering layers for every vector
field. It defaults to `'[1,1]'`: two 1-bit layers. Specify one to three layers,
each with one to four bits per dimension, or use `0` to disable quantization:

```sql
CREATE INDEX search_idx ON items
USING paradedb (id, title_embedding vector_cosine_ops, body_embedding vector_cosine_ops)
WITH (quantization = '[1,4]');

ALTER INDEX search_idx SET (quantization = 0);
REINDEX INDEX search_idx;
```

Quantization settings take effect only during `CREATE INDEX` and `REINDEX`.
Changing `quantization` with `ALTER INDEX ... SET` does not affect new or existing
segments until `REINDEX` rebuilds the index. `ALTER INDEX ... RESET (quantization)`
restores the default on the next rebuild.

By default, fields with fewer than 64 dimensions remain unquantized. Explicitly
enabling quantization requires every indexed vector field to have at least 64
dimensions.

<Warning>
  `vector_fields` is no longer accepted. Recreate indexes that explicitly store
  that option using `quantization` instead. `REINDEX` alone does not remove
  obsolete index options. An index can no longer assign different quantization
  schedules to individual fields.
</Warning>
