Create a ParadeDB index over the `mock_items` table from [Configure Your
Environment](/start/configure-your-environment). The same index supports text
search, vector search, filtering, sorting, and aggregations in the next page.

<CodeGroup>
```sql SQL
CREATE INDEX search_idx ON mock_items
USING paradedb (
  id,
  description,
  embedding vector_cosine_ops,
  category,
  rating,
  in_stock,
  created_at,
  last_updated_date,
  latest_available_time,
  metadata,
  weight_range
);
```

<Note>
  If `search_idx` already exists, drop it first with `DROP INDEX search_idx;`.
</Note>

Every indexed column is a field you can search, filter, sort, group, or
aggregate. The `key_field` index option is deprecated and ignored.

The `description` column is indexed for full-text search, `embedding`
is indexed for vector search, and fields like `rating`, `category`, and
`created_at` are available for filters, Top K queries, and facets.

For production schemas, define this index in your migration system instead of
running ad hoc SQL. The full [Create an
Index](/reference/indexing/create-index) reference includes framework-native
examples and tokenizer options.
