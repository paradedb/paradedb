The Getting Started flow teaches you how to search, retrieve vectors,
rank, filter, and aggregate inside Postgres using ParadeDB. To go to production, you’ll need to choose a deployment option, configure indexes for your queries, and size your infrastructure for your workload.

## Production Checklist

1. Choose the [deployment option](/operate/deploy/overview) that works best for you.
2. Load your data or [replicate it from an existing managed Postgres database](/operate/deploy/logical-replication/getting-started).
3. Connect your app.
4. Create and [tune](/operate/performance-tuning/overview) your indexes for production scale.
5. Confirm queries use ParadeDB with [`EXPLAIN`](/concepts/architecture#custom-scan).
6. Review the [upgrade](/operate/deploy/upgrading) and maintenance guides.

## Operational Readiness

Before cutting over traffic, verify the important paths:

- Run representative queries with `EXPLAIN` and confirm ParadeDB is used.
- Test writes and updates against indexed tables.
- Check backup, restore, and upgrade procedures.
- Set monitoring around slow queries, index size, and segment growth.

When something does not look right, compare the query plan with the relevant
query reference page and the [Read Throughput](/operate/performance-tuning/reads)
notes.
